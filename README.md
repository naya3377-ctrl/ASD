# 윤DF · YoonDF

Acrobat의 도구 구성과 Sumatra·미리보기의 간결한 읽기 화면을 참고한 오프라인 PDF 편집기입니다.
**0.9.6 preview: Windows 10/11 x64 설치 파일 및 공개 소스. Windows 실기기 실행 검증은 아직 하지 않았습니다.**

이 버전은 Python 3.12 + PySide6 / Qt Quick + PyMuPDF로 구현했습니다.
MuPDF 연산은 별도 프로세스에서 수행하고, Qt Quick이 화면을 표시합니다.
C++ 전용 프로그램이나 Sumatra와 같은 시작 속도를 검증한 제품은 아닙니다.

## 실행

### Windows 10/11, 64비트

`YoonDF-Setup-0.9.6-x64.exe`를 더블클릭하고 설치를 완료합니다.
시작 메뉴나 바탕 화면의 **윤DF**로 실행합니다.
Python, Qt, PDF 엔진, 한국어·영어 OCR 데이터를 포함하며 설치·실행에 인터넷이 필요하지 않습니다.
관리자 권한 없이 현재 사용자 계정에 설치됩니다.
이전 **비책 PDF**는 0.6.0부터 **윤DF**라는 이름을 사용합니다. 기존 설치 위에 업데이트하면
바탕 화면·시작 메뉴의 바로가기가 윤DF로 바뀌며 기존 설정을 이어서 사용합니다.

0.6.1부터 설치 시 윤DF를 **PDF 연결 프로그램**과 **Windows 기본 앱** 후보로 등록합니다.
PDF를 더블클릭해서 열려면 윤DF의 **설정 → 기본 PDF 앱 설정**을 누르고,
Windows 설정에서 `.pdf`의 앱으로 **윤DF**를 선택하세요. Windows 10에서는
‘파일 형식별 기본 앱 선택’에서 `.pdf`를 찾을 수도 있습니다.
설치 마지막 화면의 ‘기본 PDF 앱 선택 화면 열기’도 같은 설정으로 이동합니다.
기존 기본 앱은 사용자가 선택하기 전까지 유지됩니다. 포터블/소스 실행은 등록하지 않으므로
연결 프로그램 목록이 필요하면 설치 버전을 사용하세요.

0.6.2부터 탐색기에서 다른 PDF를 더블클릭하면 **실행 중인 윤DF의 새 탭**에 열립니다.
이미 열린 파일은 해당 탭으로 이동하고 미저장 편집을 유지합니다. 바탕 화면의 윤DF를
다시 실행하면 기존 창을 표시하며, 최소화했던 창은 이전 크기로 복원합니다.
주석·본문 입력이나 파일 선택 창이 열려 있으면 그 창을 닫은 뒤 새 탭을 엽니다.
슬라이드 쇼 중에 다른 PDF를 열면 읽기 화면으로 돌아와 새 탭을 표시합니다.
**0.6.1 이하에서 업데이트한 직후에는 문서를 저장하고 기존 윤DF 창을 모두 닫은 뒤
새 버전을 다시 실행해 주세요.** 이전 버전 창에는 이 전달 기능이 없습니다.

0.5.1부터는 매 설치마다 새 `versions/버전-번호` 폴더에 파일을 풀고, 모두 완료한 뒤
실행 경로를 바꿉니다. 이전 앱이 실행 중이어도 그 앱의 DLL이나 `_bz2.pyd`를 덮어쓰지 않습니다.
같은 버전을 다시 설치해도 새 폴더를 사용합니다. 기존 앱에서 문서를 저장하고 닫은 뒤,
바탕 화면의 **윤DF**를 다시 열면 새 버전이 실행됩니다.
설치 실패 시 기존 실행 경로를 유지하며, 필수 파일을 ‘무시’하고 넘어가는 설치는 허용하지 않습니다.
이전 버전 폴더는 실행 중인 앱을 보호하기 위해 유지하므로 업데이트마다 디스크 공간을 추가로 사용합니다.
앱을 제거하면 함께 정리됩니다. 제거 전에는 열린 문서를 저장하고 모든 윤DF 창을 닫아 주세요.
설정과 사용자가 저장한 PDF의 위치는 변경하지 않습니다.

설치된 `versions/0.9.6-*/source/samples/sample.pdf`로 본문 수정과 페이지 편집을 시험할 수 있습니다.
마지막 페이지는 OCR용 스캔입니다. 아래 명령은 소스를 개발할 때만 필요합니다.

### 소스 실행

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
python main.py path/to/document.pdf path/to/another.pdf
```


## 0.9.6 변경 사항

- **멈춤 기록**: 화면이 1초 넘게 멈추면 그 순간 프로그램이 하던 일과 멈춘 시간을 오류 로그에 남깁니다. PDF 처리가 1초 넘게 걸린 작업, 본문 편집 준비·적용 시간도 기록합니다. 기록은 이 컴퓨터의 로그 폴더에만 저장됩니다(설정 → 오류 로그 폴더 열기).

## 0.9.5 변경 사항

- **Type1 글꼴 PDF 편집**: 인디자인·일러스트레이터 등에서 만든 PDF에 흔한 Type1 글꼴(예: Pretendard 부분 글꼴)을 읽을 수 있습니다. Type1은 글꼴 한 조각에 256자까지만 담을 수 있어 같은 글꼴이 여러 조각으로 나뉘어 있는데, 이 조각들을 하나로 합쳐 원래 글꼴·자간·줄 위치 그대로 편집합니다. 이전에는 `Unknown CFF format` 오류로 편집이 시작되지 않았습니다.
- **자동 적용**: 편집하던 문단 바깥을 클릭하면 바로 적용됩니다. 다른 문단을 클릭하면 적용한 뒤 그 문단 편집으로 이어집니다. Esc는 취소, Ctrl+S는 파일 저장입니다.
- **편집 모드 진입 속도**: 편집 모드에서 화면으로 넘기는 정보를 문단 위치만으로 줄였습니다. 글자를 선택하지 않은 페이지는 선택 표시용 캔버스를 그리지 않습니다. 이미지 손잡이도 이미지 위치만 받습니다.
- **모드 정리**: 위쪽 모드는 **읽기 / 편집** 두 가지입니다. 주석 목록은 도구 막대의 메모 아이콘으로 열고 닫으며, 페이지 정리(썸네일 끌기·회전·삭제)는 왼쪽 사이드바에서 항상 할 수 있습니다.

## 0.9.4 변경 사항

0.9.3의 화면·탭 이동·목차·테마·최근 문서 기능을 유지하고 본문 편집 경로를 수정했습니다.

- **입력 순간 문단 전체가 밀리는 현상**: Qt 기본 TextArea에 남아 있던 왼쪽 4px 여백을 없앴습니다. PDF 편집 폭과 실제 입력 폭을 맞춰, 한 글자 입력만으로 40줄 문단이 두 배 높이로 바뀌던 사례를 수정했습니다. 줄 끝 글자 교체 때 생기는 소수점 폭 오차에도 작은 여유를 두어 원래 글자 위치를 유지합니다.
- **입력 중 반복 작업 감소**: 글자 지원 검사는 문서 수정 시에만 갱신합니다. 새 한글을 입력할 때 원문 전체의 글꼴을 다시 읽고 서식을 바꾸지 않습니다. 등록한 글꼴과 한글 대체 글꼴을 다음 편집에서도 재사용합니다.
- **한글 조합 보호**: 자음·모음을 조합하는 동안 글꼴 변경을 보류하고, 조합이 끝난 뒤 필요한 글자에 적용합니다. 취소한 편집으로 늦은 글꼴 응답이 되돌아오지 않도록 정리했습니다.
- **대체 글꼴 검사**: 이름이 한글 글꼴이더라도 필요한 글자가 실제로 없으면 내장 한글 글꼴을 사용합니다. 원래 있던 글자의 서체는 유지합니다.
- **오류 처리**: PDF 처리기가 종료되면 계속 기다리는 대신 오류를 알리고 입력 중인 글을 화면에 남깁니다. 이 경우 글을 복사해 보관한 뒤 앱을 재실행해야 합니다. 이미 처리기에만 적용한 미저장 PDF 변경의 자동 복구를 보장하는 기능은 아닙니다. 네이티브 오류 기록도 설정 → 오류 로그 폴더 열기에서 확인할 수 있습니다.

68개 단위·통합 시험 및 실제 Qt 화면 시험을 통과했습니다. 1,119자 문단을 8회 연속 수정·저장·재개방했고, 입력 이벤트 처리 시간은 이 Linux 시험에서 중앙값 2.8ms / 95백분위 20.9ms였습니다. Windows 실기기 성능 수치가 아니며, 사용자 화면의 실제 PDF는 제공되지 않았습니다. 자세한 조건과 한계는 `docs/EDITING_FIXES_094.md`에 있습니다.

## 0.9.3 변경 사항

- **편집 속도**: 본문을 고친 뒤 **바뀐 페이지만 다시 그립니다.** 다른 페이지와 썸네일은 그대로 두고, 고친 페이지도 새 그림이 준비될 때까지 이전 그림을 보여 줘서 화면이 비지 않습니다. 페이지 순서를 바꾸거나 되돌리기를 해도 이미 그린 페이지를 다시 씁니다.
- **글꼴 준비 속도**: 설치된 글꼴 목록을 디스크에 기억해서 매번 모든 글꼴 파일을 다시 읽지 않습니다. 한 번 준비한 글꼴은 같은 페이지를 편집하는 동안 재사용하고, 입력할 때마다 글꼴 처리 프로세스를 새로 띄우지 않습니다.
- **글꼴 적용**: 원본 글꼴이나 고른 글꼴에 없는 글자(예: 영문 글꼴 문단에 한글 입력)가 있어도 편집이 막히지 않습니다. 그 글자만 자동으로 한글 글꼴(Windows는 맑은 고딕)로 보여 주고 저장합니다. 굵은 글씨는 굵게 이어받습니다.
- **탭 순서 바꾸기**: 탭을 옆으로 끌어서 순서를 바꿀 수 있습니다. 탭 줄에서 휠을 굴리면 가로로 넘어갑니다.
- **새 화면 구성**: 위쪽 3줄을 탭 줄 + 도구 줄 2줄로 줄여 문서가 더 넓게 보입니다. 자주 안 쓰는 기능(PDF 결합, 다른 이름으로 저장, OCR, 정보)은 **⋯ 더 보기** 메뉴로 옮겼습니다.
- **어두운 테마**: 설정 → 화면 테마에서 Windows 설정 따르기 / 밝게 / 어둡게를 고릅니다. PDF 페이지는 원래 색 그대로 보입니다.
- **목차**: 왼쪽 사이드바의 **목차** 탭에서 PDF 책갈피를 보고 눌러서 이동합니다. 지금 읽는 부분이 표시됩니다.
- **최근 문서·읽던 위치**: 시작 화면에 최근 문서가 나오고, 다시 열면 지난번에 보던 페이지로 이동합니다. 기록은 이 컴퓨터에만 저장되며 설정에서 끌 수 있습니다.
- **배율**: 배율 버튼에 실제 크기(100% = 인쇄 크기)를 표시하고, 누르면 너비 맞춤·페이지 맞춤·50~300%를 고를 수 있습니다.

## 0.9.2 변경 사항

- 편집 중 창의 **× / Ctrl+W**를 누르면 **적용 후 닫기 · 입력 버리고 닫기 · 계속 편집**을 선택합니다. 적용한 내용의 PDF 저장 여부는 이어서 확인합니다. 여러 탭에서는 현재 탭만 닫고, **Ctrl+Shift+Q**는 전체 종료를 요청합니다.
- 글꼴 준비 중 예외가 나도 ‘확인하는 중’에 남지 않도록 오류 안내와 **다시 시도**를 추가했습니다. 글꼴 해석은 별도 프로세스에서 15초로 제한하고, 편집기 응답 대기는 25초 뒤 안내합니다. 준비 중에도 입력을 버리고 닫을 수 있습니다.
- 원본 부분 글꼴에 없는 새 한글을 입력할 때 미리보기에서 네모로 숨기지 않습니다. 저장 전 **없는 글자만 대체**를 누르면 그 글자만 내장 한글 글꼴로 바꾸며, 기존 원본 글자는 유지합니다. 원본과 정확히 같은 서체가 필요하면 해당 전체 글꼴을 선택하세요.
- 설치 버전의 실제 실행 프로세스를 `YoonDF.exe`, 파일 설명을 **윤DF**로 지정했습니다. 설정의 **오류 로그 폴더 열기**에서 로컬 진단 기록을 확인할 수 있습니다.
- 구성한 시험 문서와 Linux Qt 화면에서 검증했습니다. 사용자 원본 PDF, Windows 설치·작업 관리자 표시·실제 한글 입력기는 아직 실기기 검증하지 않았습니다.

## 0.9.1 변경 사항

- 본문 편집을 시작할 때 **원본의 각 줄 시작 위치·줄 간격·글자 사이 간격**을 함께 가져옵니다. 들여쓰기가 사라지거나 편집 시작 순간 글자 배치가 바뀌던 처리를 보완했습니다.
- 저장 과정에서 소수점 크기의 편집 영역을 반올림한 PDF 조각에 맞춰 늘리던 문제를 수정했습니다. 편집 결과를 같은 크기로 잘라 넣어 불필요한 가로·세로 배율 변화를 없앴습니다.
- 자간이 있는 문장의 마지막 글자를 같은 폭의 글자로 바꿔도 단어 전체가 다음 줄로 밀리던 문제를 수정했습니다. 글자 크기를 바꾸면 원본에서 가져온 줄 간격도 함께 조절합니다.
- 한글·영문 글꼴 검색, 입력 중 자동 높이·줄바꿈, 오른쪽 폭 조절 손잡이는 유지합니다. 본문을 수정한 뒤 **적용 → Ctrl+S**로 저장합니다.
- 시험 문서에서 **원본 → 편집 시작 → 실제 수정·저장·다시 열기**의 글자 좌표를 비교했습니다. 모든 PDF의 복합 조판을 보장하지는 않습니다. 한 줄 안의 복잡한 기준선 이동, 가로로 늘린 글자, 세로쓰기와 다른 문단/페이지로의 자동 조판은 미지원 범위입니다.

## 0.9.0 변경 사항

- **편집 → 본문 수정 → 글자 클릭** 후 원래 위치에서 바로 입력합니다. 편집 화면과 저장 결과가 같은 텍스트 레이아웃을 사용하며, 입력에 따라 줄바꿈과 상자 높이가 즉시 바뀝니다. **상자 오른쪽 손잡이**를 끌면 폭을 조절할 수 있습니다.
- PDF에 포함된 원본 글꼴을 우선 사용합니다. 일부 PDF의 부분 글꼴에서 빠진 문자표를 PDF의 문자 정보로 복구하며, 한 블록의 서로 다른 서체·크기·색·굵게·기울임을 이어받습니다. 편집을 시작만 하고 그대로 적용하면 원본 내용은 변경하지 않습니다.
- **위쪽 글꼴 목록을 누르면 검색**할 수 있습니다. 한글·영문 이름, 설치된 TTF/OTF 및 TTC/OTC의 개별 서체를 찾습니다. 글꼴 파일을 직접 선택할 수도 있습니다.
- 원본 부분 글꼴에 새 글자가 없으면 정확히 일치하는 설치 글꼴을 확인합니다. 그래도 없으면 작성 중인 내용을 유지하고 위쪽 안내줄에 표시합니다. 같은 전체 글꼴을 설치하거나 사용자가 검색해서 선택해야 하며, 알리지 않고 기본 글꼴로 바꾸지 않습니다.
- 늘어난 글이 아래 본문과 겹치거나 페이지를 넘으면 안내합니다. 편집 영역 내부의 줄바꿈을 지원하며, **다른 문단을 아래로 밀거나 다음 페이지로 자동 조판하지는 않습니다.** 원본의 복잡한 자간·커닝·수식·세로쓰기와 스캔 이미지의 직접 수정은 지원 범위가 아닙니다.
- 적용 후 같은 본문을 다시 편집하는 과정, 페이지를 오가는 작성 상태, 기존 메모·이미지·여러 장 이동 기능을 점검했습니다. 휠 입력 코드는 그대로 유지했습니다.

## 0.8.0 변경 사항

- 메모·답글은 PDF 옆 주석 패널에서 작성합니다. 입력하는 동안 페이지를 가리거나 어둡게 하지 않으며, 두 페이지 보기와 스크롤을 유지합니다.
- **읽기 모드에서 메모 아이콘을 드래그**하면 글자와 관계없이 페이지 안의 원하는 위치에 놓을 수 있습니다. 메모 내용·답글은 유지하며 이동한 위치는 PDF에 저장됩니다. 회전된 페이지도 지원합니다.
- 기존 형광펜이나 주석을 **본문에서 우클릭 → 형광펜 삭제 / 주석 삭제**로 지웁니다. 삭제한 주석과 연결 답글은 Ctrl+Z로 복원할 수 있습니다.
- **편집 → 본문 수정 → 글자 클릭**으로 페이지 위에서 직접 입력합니다. 위쪽 도구줄에서 원본/설치/파일 글꼴, 크기와 영역 높이를 고르고 적용하거나 취소합니다. 화면에 없는 페이지로 이동해도 작성 중인 내용은 유지됩니다.
- **편집 → 이미지 이동·크기**에서 윤DF로 삽입한 이미지를 드래그하고 오른쪽 아래 손잡이로 비율을 유지해 크기를 바꿉니다. 0.7.0에서 삽입한 독립 이미지도 지원하며 위치와 크기는 PDF의 실제 이미지 객체에 저장됩니다. 다른 프로그램에서 복잡하게 배치한 모든 이미지의 이동을 보장하지는 않습니다.
- 왼쪽 썸네일을 **Ctrl+클릭**하면 떨어진 페이지를, **Shift+클릭**하면 연속 페이지를 선택합니다. 선택한 썸네일 하나를 끌어 삽입 선에 놓으면 여러 장이 원래 순서를 유지해 함께 이동합니다. 한 번의 Ctrl+Z로 전체 이동을 되돌립니다.
- 두 페이지 보기에서도 썸네일은 모든 페이지를 표시합니다. 기존 휠 입력 처리는 유지했습니다.

## 0.7.0 변경 사항

- 창 오른쪽 위 X는 현재 탭을 닫고, 마지막 탭에서만 앱을 종료합니다. **Ctrl+Shift+Q**는 모든 탭을 확인 후 종료합니다. 미저장 내용은 저장/취소를 선택할 수 있습니다.
- 탭 상태 갱신 중에도 클릭이 유지되도록 목록 모델을 변경했습니다. 선택 표시와 실제 문서가 같은 상태를 사용합니다.
- 두 페이지 보기는 탭마다 기억하며, 방향키/Page Up·Down은 펼침 단위로 이동합니다. 검색·썸네일은 해당 페이지로 정확히 이동합니다. 마지막 홀수 페이지는 가운데에 표시합니다. 슬라이드 쇼는 한 장씩 표시하고 종료하면 원래 배치로 돌아옵니다.
- 형광펜·밑줄·취소선을 적용할 때 주석 패널이나 메모 입력을 자동으로 열지 않습니다. 각주(메모)는 별도 동작이며 PDF의 표준 Text 주석입니다. 자동 번호가 붙는 본문 하단 각주 조판 기능은 아닙니다.
- PDF의 래스터 이미지를 우클릭해 원본 화소 크기의 PNG로 복사·저장합니다. 알파 마스크와 인라인 이미지를 지원합니다. 벡터 도형이나 여러 요소로 구성된 차트의 통합 추출은 지원하지 않습니다. 문서의 복사 제한을 존중합니다.
- 이미지 삽입은 파일 선택 즉시 현재 페이지에 표시합니다. 크기는 페이지에 맞춰 제한하고 가로세로 비율을 유지합니다. Ctrl+Z로 취소할 수 있습니다.
- 본문 교체는 **원본 글꼴 유지**가 기본입니다. 정확히 일치하는 설치 글꼴이나 PDF에 포함된 글꼴을 재사용하며, 새 글자의 글리프가 없으면 오류를 알려주고 입력 내용을 유지합니다. 설치된 TTF/OTF 목록 또는 글꼴 파일에서 직접 선택할 수 있습니다. 여러 글꼴이 섞인 블록은 적용할 글꼴 하나를 선택해야 합니다. 글꼴 크기·색상을 이어받지만 원본의 복합 조판/자간을 완벽히 재현하지는 않습니다.

영역 높이를 늘릴 때 아래의 다른 내용과 겹치지 않는지 화면에서 확인하세요.

OCR는 복사·검색용 문자층을 만드는 기능입니다. 원본 스캔 이미지의 글자 모양은 바꾸지 않습니다.
기울어진 글자·세로쓰기·복잡한 중첩 텍스트와 이미지의 자유 이동/교체는 이 버전의 편집 범위에 포함되지 않습니다.

## 읽기·검색

- PDF 파일을 끌어 놓거나 Ctrl+O로 엽니다. 여러 파일을 선택하면 각각 새 탭으로 열립니다.
- 연속 스크롤, 확대·축소, 너비 맞춤을 지원합니다. 현재 확대 비율 버튼은 너비 맞춤으로 돌아갑니다.
- 읽기 모드에서 글자를 드래그하고 Ctrl+C 또는 우클릭으로 복사합니다. 가로·여러 줄·회전된 글자 선택, 더블클릭 단어 선택, Ctrl+A 현재 페이지 전체 선택을 지원합니다. 선택 범위는 한 페이지 안입니다.
- PDF의 웹·이메일 링크는 기본 브라우저/메일 앱으로, 내부 페이지 링크는 해당 페이지로 이동합니다. 링크 위에서 드래그하면 텍스트를 선택합니다. 외부 파일 실행 링크는 지원하지 않습니다.
- 무한 휠은 모든 각도 입력을 누적해 스크롤합니다. **설정**에서 Windows 휠 줄 수에 적용할 배율을 조절할 수 있습니다. Ctrl+휠은 확대·축소, Shift+휠은 가로 스크롤입니다.
- Ctrl+F로 검색하면 첫 결과의 문장 위치까지 이동합니다. 결과 클릭, Enter/F3로 다음, Shift+Enter/Shift+F3로 이전 결과로 이동합니다. 현재 결과는 주황색, 다른 결과는 노란색으로 표시합니다. 같은 페이지 안의 여러 결과도 차례로 이동하며 마지막 결과 다음에는 처음으로 돌아갑니다.
- 암호가 있는 PDF는 열 때 암호를 입력합니다. 편집·복사·인쇄 제한은 그대로 적용합니다.
- 페이지 회전과 페이지 크기가 서로 다른 문서를 처리합니다.

## 슬라이드 쇼 · 키보드 페이지 이동

상단 **슬라이드 쇼** 버튼 또는 **F5 / F11 / Ctrl+L**로 현재 페이지부터 시작합니다.
도구 모음을 숨긴 전체 화면에 한 페이지 전체를 맞추며, 세로·가로·회전된 페이지도 잘리지 않게 표시합니다.
별도의 자동 넘김은 없으며 직접 페이지를 넘기는 발표 모드입니다.

| 동작 | 키 |
| --- | --- |
| 다음 페이지 | → / ↓ / Page Down / Space |
| 이전 페이지 | ← / ↑ / Page Up / Shift+Space |
| 첫 페이지 / 마지막 페이지 | Home / End (Ctrl+Home / Ctrl+End도 지원) |
| 슬라이드 쇼 시작·종료 | F5 / F11 / Ctrl+L |
| 슬라이드 쇼 종료 | Esc 또는 하단 종료 버튼 |

페이지 이동 키는 일반 읽기 화면에서도 **화면 높이가 아닌 PDF 한 장 단위**로 동작합니다.
검색창·페이지 번호·주석 등 입력란에서는 커서 이동과 입력을 우선하고, 대화상자가 열려 있을 때는
페이지 이동과 슬라이드 쇼 시작을 막습니다. 첫 페이지와 마지막 페이지에서는 더 넘어가지 않습니다.

슬라이드 쇼에서는 빈 곳을 왼쪽 클릭하면 다음, 오른쪽 클릭하면 이전 페이지로 이동합니다.
휠 입력은 한 장씩 이동하는 데 사용하며 일반 읽기 화면의 무한 휠 동작은 그대로입니다.
PDF 안의 웹 링크와 내부 페이지 링크도 클릭할 수 있습니다.
하단 이동·종료 도구와 커서는 잠시 후 숨겨지고 마우스를 움직이면 다시 나타납니다.
종료하면 마지막으로 보여준 페이지에서 읽기를 이어 갑니다. 페이지를 넘기지 않았다면 원래 읽던 위치로,
넘겼다면 해당 페이지 상단으로 돌아옵니다. 확대율·사이드바·편집 도구와 원래 창 상태를 유지합니다.
슬라이드 쇼 중에는 탭 전환·편집 단축키와 새 자동 OCR 시작을 막습니다.

## 문서 탭

- 각 탭의 읽던 위치·확대율·검색어·편집 내용·실행 취소 기록을 따로 유지합니다.
- Ctrl+Tab / Ctrl+Shift+Tab: 다음 / 이전 탭, Ctrl+W: 현재 탭 닫기, Ctrl+T: 빈 탭.
- 탭의 × 또는 휠 가운데 버튼으로 닫습니다. 탭이 많으면 가로 스크롤이나 오른쪽 **열린 문서 목록**을 사용합니다.
- 이미 열린 경로는 기존 탭을 선택합니다. 다른 열린 PDF 경로로 덮어쓰기는 막습니다.
- 저장하지 않은 탭을 닫을 때 저장 / 버리기 / 취소를 선택합니다. 저장 실패 시 탭과 편집을 유지합니다. 창 종료 시 숨겨진 탭도 확인합니다.
- 탭 전체가 PDF 엔진 프로세스 1개, 공유 프레임 2개와 이미지 캐시 한도를 공유합니다. 숨겨진 탭은 렌더 대기 요청과 텍스트 좌표 캐시를 비웁니다. 자동 OCR는 현재 탭에서 시작하며 다른 OCR 작업이 끝날 때까지 추가 자동 작업을 시작하지 않습니다.
- 기본 이미지 캐시 512MiB + 썸네일 64MiB는 모든 탭의 합계입니다. PDF 구조·편집 이력·화면 텍스처·OCR·인쇄 메모리는 별도이며 전체 메모리에 대한 상한은 아닙니다.
- 닫은 탭이나 앱 재시작 시 세션 자동 복원은 아직 지원하지 않습니다.

## PDF 표준 주석 · Acrobat과 공유

상단 **주석**에서 형광펜·밑줄·취소선·메모, 작성자와 색상을 선택합니다.
글자를 먼저 선택한 뒤 도구를 누르거나, 도구를 선택하고 드래그할 수 있습니다.
읽기 모드의 글자 선택 우클릭 메뉴에서도 같은 주석을 추가할 수 있습니다.
본문 위의 주석 또는 오른쪽 목록을 클릭하면 해당 위치로 이동하며 **수정 / 답글 / 삭제**를 사용할 수 있습니다.
삭제는 연결된 답글을 포함합니다. Ctrl+Z로 복구하고 Ctrl+S로 PDF에 저장합니다.

- 메모는 `/Text`, 텍스트 표시는 `/Highlight`, `/Underline`, `/StrikeOut` 주석으로 저장합니다.
- 선택한 글자의 방향을 반영한 `/QuadPoints`, Unicode 작성자 `/T`·내용 `/Contents`,
  작성·수정 시각, 식별자 `/NM`, 표시 스트림 `/AP`를 PDF에 기록합니다.
- 답글은 같은 페이지의 원래 주석을 가리키는 `/IRT`와 `/RT /R`을 사용합니다.
  별도 파일이나 페이지 이미지로 평면화하지 않습니다.
- 다른 프로그램의 메모·형광펜·밑줄·취소선·물결 밑줄을 읽고 내용·작성자·색상을 수정할 수 있습니다.
- 내용만 수정할 때 기존 표시 스트림·팝업·작성 시각·검토 상태와 사용자 정의 필드를 유지합니다.
  기존 서식 있는 댓글 본문을 수정하면 그 댓글은 일반 텍스트로 바뀝니다.
- 잠긴 주석, 그룹 주석, 검토 상태 기록, 자유 텍스트·스탬프·펜·도형 등은 목록과 PDF 표시를 유지하지만
  이 버전의 수정·삭제 대상에는 포함하지 않습니다. 지원하지 않는 답글이 연결된 주석은 함께 삭제하지 않습니다.
- 주석 권한과 본문 편집 권한을 따로 적용합니다. 선택 기반 주석에는 텍스트 선택/복사 권한도 필요합니다.
- Adobe의 클라우드 공유 검토, 전자서명 유지, FDF/XFDF 가져오기·내보내기는 지원하지 않습니다.

표준 객체·한글 정보·답글 연결을 별도 PDF 파서(pypdf)로 확인했고 Poppler로 화면을 검증했습니다.
**Adobe Acrobat/Reader 실기기에서 주고받으며 편집한 검증은 아직 완료하지 않았습니다.**
`samples/annotation-compatibility.pdf`를 Acrobat의 주석 패널에서 열어 확인할 수 있습니다.
확인 절차는 `docs/ANNOTATION_COMPATIBILITY.md`에 있습니다.

## 여러 PDF 결합

상단 **PDF 결합 → PDF 추가**에서 여러 파일을 선택합니다. 결합 대화상자에 여러 PDF를 끌어 놓아도 됩니다.
메인 읽기 화면에 놓으면 각각 새 탭으로 열립니다.
미리보기와 페이지 수를 확인하고 화살표로 파일 순서를 정한 뒤 **결합하여 저장**을 누르세요.
**현재 문서 추가**는 저장 전 편집 내용도 함께 반영합니다. 원본 파일은 변경하지 않습니다.
결과는 새 PDF로 저장되며, **결합한 PDF 열기**로 바로 확인할 수 있습니다.

페이지 내용·주석·웹/문서 내 링크·양식을 복사하고, 각 파일을 묶는 책갈피와 원래 페이지 책갈피를 추가합니다.
같은 이름의 양식 필드는 별개 항목으로 유지합니다. 암호가 있는 문서는 암호를 입력해야 하며,
결합 권한이 없으면 소유자 암호가 필요합니다. 출력 파일은 암호화하지 않습니다.
결합은 PDF 구조를 다시 만드는 작업이므로 전자서명의 검증 상태는 유지되지 않습니다.
취소는 현재 파일 복사 후 반영되며, 취소·실패 시 기존 출력 파일을 덮어쓰지 않습니다.

## 인쇄

상단 **인쇄** 또는 **Ctrl+P**로 기본 인쇄 창을 엽니다. 프린터, 페이지 범위, 현재 페이지,
선택한 썸네일의 페이지, 매수, 용지 방향을 지정할 수 있습니다. 수정 중인 내용도 인쇄됩니다.
페이지는 프린터의 인쇄 가능한 영역에 비율을 유지해 맞춥니다. 인쇄 진행 창에서 취소할 수 있습니다.
이 버전은 최대 300dpi 래스터 인쇄입니다(문서의 저해상도 인쇄 제한이 있으면 150dpi).
따라서 'PDF로 인쇄' 결과에는 원본 벡터·선택 가능한 문자층이 보존되지 않습니다.
문서를 PDF 그대로 전달하려면 **저장**을 사용하세요.

## OCR 설치와 사용

Windows 설치 파일에는 OCR 엔진과 한국어·영어 데이터가 포함되어 있습니다. PDF를 서버에 업로드하지 않습니다.
소스로 실행할 때는 프로젝트의 `tessdata` 폴더를 사용하며, 없으면 별도 설치한 Tesseract를 찾습니다.

### 다른 언어를 추가하거나 별도 Tesseract를 사용할 때

Tesseract 공식 문서가 안내하는 Windows 설치 경로를 사용하세요:
https://tesseract-ocr.github.io/tessdoc/Installation.html

일반적으로 `C:\Program Files\Tesseract-OCR\tesseract.exe` 설치를 자동으로 찾습니다.
그 외 경로는 `tesseract.exe`가 있는 폴더를 PATH에 추가합니다.
언어 데이터 폴더에 `eng.traineddata`, `kor.traineddata`를 넣어 영어와 한국어를 사용할 수 있습니다.
공식 언어 데이터: https://github.com/tesseract-ocr/tessdata_fast

```powershell
tesseract --list-langs
```

목록에 `kor`와 `eng`가 있으면 앱 OCR 창에서 `kor+eng`를 선택할 수 있습니다.
설치되지 않은 언어는 선택 목록에 표시하지 않습니다.

### 동작

일반 PDF는 OCR 없이 곧바로 글자를 선택합니다. 기본으로 켜진 **스캔 자동 OCR**은 현재 보는 페이지에 문자층이 없을 때 약 0.9초 후 인식을 시작합니다. 빠르게 지나가는 페이지나 문서 전체를 열자마자 모두 인식하지 않습니다.
**OCR** 버튼에서는 현재/선택/전체 페이지를 지정할 수 있습니다. 문자층이 있는 페이지는 건너뜁니다.
인식 도중에도 읽기·검색·이동을 할 수 있으며, 문서 변경과 새 파일 열기는 완료/취소 후 가능합니다.
취소한 작업의 부분 결과는 적용하지 않습니다. 완료 후 **저장**해야 문자층이 PDF에 반영됩니다.
원본 페이지를 다시 이미지로 바꾸지 않고, Tesseract의 숨겨진 문자층만 추가합니다.
빈 페이지·인식하지 못한 페이지에는 텍스트를 추가하지 않습니다.

## Windows 실행 파일 만들기

`BUILD_WINDOWS.cmd`는 별도 빌드 환경을 만들고 테스트 후 다음 파일을 생성합니다.

```text
dist/YoonDF/YoonDF.exe
```

같은 폴더의 `_internal` 등 모든 파일이 함께 있어야 합니다.
단일 exe가 매번 압축을 푸는 방식 대신 폴더형 패키지를 사용합니다.
Inno Setup 6에서 `packaging/windows.iss`를 컴파일하면 설치 파일을 만들 수 있습니다.

GitHub 저장소에 이 프로젝트를 올리면 `.github/workflows/windows-build.yml`이 Windows에서 테스트·패키징합니다.
Actions 실행이 성공하면 Artifacts에서 설치 파일과 실행 폴더를 내려받습니다.
이 workflow는 자동으로 공개 Release를 만들지 않습니다.
배포한 설치 파일은 `packaging/CROSS_BUILD.md`의 CPython 임베디드 런타임·NSIS 경로로 교차 빌드했습니다. Windows 실기기 시험은 아직 하지 않았습니다.

## 구현과 성능

- GUI와 PDF 엔진을 별도 프로세스로 분리. PyMuPDF를 여러 스레드에서 동시에 호출하지 않습니다.
- 보이는 페이지와 근처 페이지만 렌더링. 본문 렌더링을 썸네일보다 우선 처리합니다.
- 본문 이미지 캐시는 기본 512MiB. **설정**에서 256MiB / 512MiB / 1GiB 중 선택할 수 있습니다.
- 썸네일은 별도 64MiB 캐시로 보관하므로 큰 페이지를 확대해도 미리보기가 밀려나지 않습니다.
- GUI가 소유하는 공유 프레임 2개(총 약 92MiB)를 재사용하여 PNG 압축·해제 및 큰 IPC 복사를 생략합니다. 공유 메모리 할당 실패 시 PNG 전달로 돌아갑니다.
- 보이는 페이지에 640픽셀 첫 화면을 먼저 보내고, 디스플레이 해상도로 다시 선명하게 표시합니다.
- MuPDF 디스플레이 리스트를 최대 8페이지 재사용합니다. Qt/GPU 자원과 PDF 엔진 메모리는 캐시 설정 외에 별도로 사용합니다.
- 화면 렌더는 최대 폭 3600픽셀, 최대 1600만 픽셀로 제한합니다.
- OCR는 또 다른 프로세스에서 실행하고, Tesseract 내부 스레드는 2개로 제한합니다.
- 편집 이력은 디스크 스냅샷 방식으로 최대 20단계, 이력 파일 합계 약 384MiB를 기준으로 오래된 항목부터 정리합니다. 큰 단일 문서의 최소 한 단계는 남습니다. 큰 PDF의 편집·저장은 시간이 걸릴 수 있습니다.
- 임시 파일은 OS 임시 폴더에 있으며 정상 종료 시 정리됩니다. 비정상 종료 후 `bichaek-*` 임시 폴더가 남을 수 있습니다.
- Windows 화면 표시는 Qt Quick의 Direct3D 11 GPU 백엔드를 사용합니다. PDF 해석과 문자 인식은 CPU에서 수행합니다. 화면 표시 문제가 있으면 **설정 → 호환 모드** 선택 후 재실행할 수 있습니다. 검증 환경은 Linux 오프스크린 소프트웨어 렌더링이며 Windows GPU 성능은 측정하지 않았습니다.

## 검증

```sh
python -m unittest discover -v
python scripts/qa_ui.py
python scripts/qa_reader.py
python scripts/qa_upgrade.py
python scripts/qa_tabs.py
python scripts/qa_annotations.py
```

PDF 통합 시험은 한글/영문 교체, 저장 후 추출, 이전 텍스트 제거, 실패 롤백, 페이지 재배열,
회전 좌표, 삽입·삭제·실행 취소, 이미지·주석, OCR 후 검색과 원본 픽셀 보존을 확인합니다.
OCR 시험은 영어 Tesseract가 설치된 환경에서 실행합니다. 한국어 OCR 정확도는 별도 검증이 필요합니다.
`scripts/qa_ui.py`는 Linux 등 오프스크린 환경에서 실제 QML 창과 편집 대화상자를 시험하는 개발용 도구입니다.

문서 보존에 영향을 주는 변경이므로 중요 원본의 첫 시험은 **다른 이름으로 저장**을 권장합니다.
고급 양식, 전자서명 유지, PDF/A 유지, 복잡한 링크·목차의 편집 후 무결성은 별도 검증 대상입니다.
