# 윤DF 1.0.4 · 소스 릴리스

2026-09-29 · 입력: YoonDF-1.0.3-source.zip

## 적용한 디자인

- 기존에 승인한 파란 문서형 윤DF 로고의 PNG 바이트를 그대로 적용. 중앙은 비우고 문서 하단에 윤DF가 들어간 원본이다.
- PNG, 호환용 SVG 래퍼, 다중 크기 Windows ICO를 일치시켰다. 창·실행 파일·설치 프로그램은 이 아이콘을 사용한다.
- 흰 시작 화면, 밝은 중성 회색 도구 모음, 파란 강조색, 정돈한 모서리와 여백.
- 시작 로고는 한 번만 나타나며 파일이 열리면 즉시 끝난다. 버튼 반응 120ms, 메뉴·대화상자 열기 120–180ms.
- 닫기 전환은 즉시 완료하여 다음 클릭을 가로막지 않는다. 문서 열기·저장·입력을 애니메이션이 기다리게 하지 않는다.
- 설정의 ‘움직임 줄이기’를 저장한다. 켜면 장식적 전환을 끈다.
- **사이드바 페이지 미리보기에는 이동·확대·페이드가 없다.** 선택·미리보기 교체·자동 위치 맞춤은 즉시 처리한다. 사용자의 스크롤과 페이지 드래그 기능은 유지한다.

## 수정한 버그

1. **다른 탭의 파일 이름이 바뀌는 문제**: 이름 입력 중 다른 탭으로 이동하면 갱신된 활성 문서를 대상으로 이름 변경이 실행되는 것을 재현했다. 입력을 시작한 문서를 기록하고 현재 문서와 일치할 때만 적용하며, 탭을 떠나면 입력을 취소한다. 두 파일의 경로와 디스크 파일을 검사하는 회귀 시험을 추가했다.
2. **링크 이동 직후 휠 입력이 되돌아가는 문제**: 예약된 페이지 위치 복원이 수동 휠 이동을 덮어썼다. 휠 이벤트를 처리하기 전에 예약 복원을 중단한다. 10배·분할·픽셀 휠 입력과 Ctrl 확대/축소 검증을 유지하고, 복원 중 입력 우선권 시험을 추가했다.
3. **대화상자 닫기 직후 클릭이 차단되는 문제**: 실제 제품 스타일 검증에서 닫기 페이드 동안 모달이 남아 다음 취소 버튼 클릭이 무시되는 것을 확인했다. 닫기를 즉시 처리하도록 수정했다.
4. 키보드 초점을 받은 탭 닫기·최근 문서 제거 버튼이 투명하게 남지 않게 했다. 강조 버튼·스위치 초점 표시를 보강했다.

## 재현과 검증

단위·통합 시험 **94개**, 실제 제품 스타일의 UI 검사 **21종**이 최종 통과했다. 건너뛴 UI 검사는 없다.
초기 실패 후 원인을 수정한 재시험의 기록도 보존했다.
검증 기록은 `1.0.4/qa/`에 있고 화면은 `1.0.4/`에 있다.
개발 의존성을 설치한 뒤 `python -m unittest discover -v`, `python scripts/run_qa.py`로 다시 실행할 수 있다.
UI 시험은 실제 QML 창에서 QtTest 키·포인터·휠·IME 이벤트를 사용하며 제품의 YoonDF 컨트롤 스타일로 실행한다.

## 반복 편집 측정

1,119자 시험 문단을 8회 수정·저장·재열기했다. 한 글자 입력 처리 중앙값 약 4.45ms,
95백분위 약 14.51ms, 적용 약 0.28–0.39초였다. 원본 글꼴을 준비하고 편집을 시작하기까지는
약 1.22–11.28초의 대기가 남는다. 준비 중 표시를 제공하지만 모든 PDF에서 즉시 편집 가능하다고 보장하지 않는다.
이는 이 Linux 시험 문서의 측정이며 Windows나 사용자 실제 PDF의 성능 수치가 아니다.

## 검증 범위의 한계

- Linux, Python 3.12, Qt/PySide6 6.8.3, PyMuPDF 1.26.6의 offscreen/software 환경이다.
- Windows 실기기 설치·바로가기 캐시·작업 표시줄·네이티브 IME·GPU 가속 및 실제 프린터 출력은 시험하지 않았다.
- OCR은 시험 문서의 한글/영문 문자층을 검사했으며 임의 스캔의 인식 정확도를 보장하지 않는다.
- 실제 Acrobat 왕복, 전자서명·PDF/A 유지, 모든 외부 PDF·글꼴 조합의 무결성을 보장하는 전수시험은 아니다.
- 이 ZIP은 실행 가능한 전체 소스와 빌드 스크립트다. Windows 설치 EXE를 새로 빌드한 결과물은 포함하지 않는다.
