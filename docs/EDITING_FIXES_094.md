# 0.9.3 편집 검토와 0.9.4 수정

검토 입력: 사용자가 제공한 YoonDF-0.9.3-source.zip과 Windows ‘응답 없음’ 화면.
스크린샷에 나온 고정수 프로시딩 원본 PDF, 오류 로그, Windows 덤프는 제공되지 않았다.
따라서 아래 재현은 구성한 PDF와 Linux Qt 화면에 대한 것이며 사용자 PC의 비정상 종료 원인을 하나로 확정하지 않는다.

## 재현한 문제

1. Qt Basic/TextArea.qml은 `leftPadding: padding + 4`를 사용한다. 앱에서 `padding: 0`만 지정하여, 처음 문서를 붙일 때 197.015pt였던 QTextDocument 폭이 입력 시 193.015pt로 줄었다. 40줄/1,119자 한글 문단의 높이가 481pt에서 961pt로 바뀌고 적용할 수 없게 됐다. 네 방향 padding과 textMargin을 모두 명시했다.
2. `canApply`와 `canUseFallback`을 읽을 때마다 모든 텍스트 조각·글자의 지원 여부를 재검사했다. QTextDocument revision과 글꼴 변경에 따라 결과를 무효화하고 재사용한다. 중복 size/changed 통지와 레이아웃 재진입도 줄였다.
3. 없는 글자 입력 후 400ms 타이머가 원문 전체 글꼴 요청과 `_reformat`을 반복했다. 해당 글자에만 대체 서식을 적용하며, 같은 대체 프로그램과 QRawFont를 재사용한다. 같은 폭을 가진 글자 교체에도 Qt의 소수점 tracking 반올림 때문에 단어가 넘어가는 경우를 재현했고, 글자 좌표는 그대로 두고 편집 폭에 0.25pt 여유를 추가했다.
4. 이름이 Noto Sans KR인 Latin 전용 부분 글꼴을 대체 글꼴로 선택하여 ‘마지막’을 저장하지 못하는 사례를 재현했다. 프로그램의 실제 문자 지원 여부를 검사하고, 부족하면 내장 한글 글꼴로 처리한다. 모든 Unicode 문자나 모든 이모지를 지원한다는 뜻은 아니다.
5. 한글 조합 중 완료된 글꼴 응답이 문서를 변경할 수 있었다. 조합이 끝날 때까지 반영을 보류한다. 취소·종료·엔진 실패 후 늦은 응답은 무효화한다.
6. 실제 PDF worker를 종료시켰을 때 미완료 요청이 남는 경우를 시험했다. 오류를 전달하고 busy 상태를 풀며 초안은 유지한다. 종료한 처리기에 보내지 못한 큰 요청이 남아도 앱 종료가 큐 배출 대기에서 멈추지 않도록 정리한다. 앱 전체가 충돌해도 미저장 PDF를 복구하는 기능을 구현했다는 뜻은 아니다.

## 검증

- Linux / Python 3.12 / PySide6 6.8.3 offscreen, software / PyMuPDF 1.26.6.
- 단위·통합 68개 통과. 기존 원본 글자 좌표 비교 오차 0.08pt 이내 검사 유지.
- `qa_edit_performance.py`: 두 단의 한글 시험 PDF, 1,119자 문단, 실제 QML/IME commit 이벤트, 8회 수정·적용·저장·재개방. 원문 줄 유지, 입력 폭 유지, 최종 한글 추출, 편집 계속/취소 확인.
- 입력 이벤트 처리 중앙값 2.819ms, 95백분위 20.917ms, 최대 31.377ms. 편집 준비 0.318–0.596초, 적용 완료 0.090–0.162초. 전체 구간의 GUI heartbeat 최대 간격 166.446ms. 준비·PDF 적용 시에도 항상 16ms 이내라는 보장은 아니다.
- 수치는 테스트 장비의 한 번의 측정으로 Windows 실제 키보드/IME, GPU, 대용량 PDF의 속도를 보증하지 않는다. `benchmarks/editing-094.json`에 원측정값을 보관한다.
- `qa_font_editing.py`, `qa_recovery.py`, `qa_editor_release.py`, `qa_direct_editing.py`, `qa_settings.py`, `qa_external_open.py` 통과. 탭, 두 페이지, 주석/이미지 이동, 다중 페이지 정리, 글꼴 검색, 저장·닫기, 외부 파일 전달 검증. QML 오류 없음.
- 실제 화면: `editing-094.png`. 같은 이름의 사용자 PDF를 재현한 것이 아니라 합성 시험 문서다.
- Windows 설치 파일은 원본 런타임을 유지하고 x64 실행기/호스트 0.9.4를 교차 컴파일했다. 추출 파일의 바이트, 소스 ZIP, NSIS CRC, 버전 정보를 검사한다.

Windows 설치·실행·네이티브 IME·GPU·사용자 원본 PDF 검증은 미완료다. 실제 종료가 계속되면 설정 → 오류 로그 폴더 열기의 최근 app/native 로그와 문제 PDF로 추가 재현이 필요하다.
