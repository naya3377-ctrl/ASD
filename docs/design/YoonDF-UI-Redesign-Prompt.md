# 윤DF UI 리디자인 프롬프트

아래 프롬프트를 윤DF 소스와 수정한 로고 PNG에 함께 첨부해서 사용한다.

---

너는 데스크톱 생산성 앱을 설계하는 시니어 프로덕트 디자이너이자 PySide6·Qt Quick/QML 개발자다. 첨부한 윤DF(YoonDF) 소스를 검토하고, 기존 기능과 편집 안정성을 유지하면서 실제 앱의 UI를 리디자인하라. 첨부한 화이트·잉크 차콜 Y 로고를 시각적 기준으로 사용하라. 버튼·메뉴·패널에는 아래의 절제된 모션 규칙을 실제로 적용한다.

## 1. 목표와 작업 범위

애플 생산성 앱에서 느껴지는 정돈된 위계, 정확한 정렬, 여유 있는 간격, 조용한 색 사용을 윤DF에 맞게 구현한다. 핵심은 문서를 오래 읽고 편집하기 편한 Windows 데스크톱 앱이다. 플랫한 면과 얇은 경계를 중심으로 설계하고, 그림자는 문서와 팝업의 층위를 구분할 때만 약하게 사용한다. 과한 뉴모피즘, 부풀어 오른 버튼, 금속·유리 재질, 광택, 장식용 그라데이션은 사용하지 않는다. macOS의 창 버튼을 흉내 내지 말고 Windows 창 조작 방식을 유지한다.

실제 QML UI를 수정하라. 웹사이트·대시보드로 새로 만들거나 프레임워크를 교체하지 않는다. 요청 범위는 시각 디자인, 필요한 레이아웃 조정, 아래에 지정한 인터랙션 애니메이션이다. PDF 처리 엔진, 편집·저장 로직, 작업 프로세스 구조, 공개 API와 데이터 모델은 유지한다. 디자인 변경에 직접 필요하지 않은 리팩터링과 기능 추가는 하지 않는다.

## 2. 색과 서체

밝은 테마의 기준 색은 다음과 같다. 기존 Theme 토큰에 의미를 맞춰 반영한다.

- 로고 타일·도구줄·사이드바: 순백색 `#FFFFFF`
- 앱 배경: 화이트 `#FFFFFF`
- 문서 주변 작업 영역: 밝은 중성 회색 `#F5F5F7`
- 주요 글자·아이콘: 잉크 차콜 `#29313A`
- 보조 글자: 중성 그레이 `#62666C`
- 경계선: `#E3E5E8`
- 선택·포커스: 절제된 블루 `#466985`
- 선택 배경: 옅은 블루 그레이 `#E3EAF0`

화이트는 노란 기가 없는 중성 흰색으로 유지한다. 아이보리·베이지·크림색을 사용하지 않는다. 강조색은 활성 도구, 선택 페이지, 포커스와 주요 동작에 제한한다. 로고, 제목, 일반 버튼 전체를 강조색으로 칠하지 않는다. 오류·경고는 기존 의미를 유지하면서 새 팔레트에 맞춘다. 기존 밝게·어둡게·시스템 설정은 유지하고, 어두운 테마에도 같은 역할별 색 체계를 적용한다. 낮은 대비로 비활성 상태와 일반 상태가 혼동되지 않게 한다.

UI는 산세리프 계열로 통일한다. Pretendard를 사용할 수 있으면 우선 적용하고, Windows에서는 Segoe UI Variable·맑은 고딕 순으로 적절히 대체한다. SF Pro 설치를 전제로 하지 않는다. 일반 UI는 14px, 보조 정보는 12–13px, 패널 제목은 15–16px을 기준으로 하되 Windows 배율에 대응한다. 일반 문장은 Regular, 선택 상태와 제목은 Medium 또는 Semibold를 사용한다. 모든 글자를 굵게 만들지 않는다. UI 글꼴 변경은 PDF 본문의 원본 서체·자간·줄바꿈에 절대로 적용하지 않는다.

## 3. 화면 구성

상단은 문서 탭, 그 아래는 핵심 도구줄, 왼쪽은 페이지·책갈피·검색 탐색, 가운데는 PDF, 오른쪽은 필요할 때 여는 주석 패널로 정리한다. 실제 소스에서 이미 제공되는 기능을 이 위계에 맞춰 배치한다.

- 탭은 약 36px 높이로 정리한다. 활성 탭, 수정 상태, 닫기 버튼을 명확히 구별하고 긴 파일명은 자연스럽게 줄인다. 현재 탭과 실제 표시 문서의 일치를 유지한다.
- 기본 도구줄은 약 48px 높이로 설계한다. 읽기·편집 전환, 자주 사용하는 주석 도구, 검색, 확대·축소, 페이지 보기 등 기존 핵심 기능을 작은 그룹으로 묶는다. 창이 좁을 때는 낮은 우선순위 동작을 더보기로 옮겨 잘림을 막는다.
- 활성 도구는 차분한 선택 배경과 또렷한 아이콘으로 표시한다. 아이콘은 기존 SVG 자산을 우선 사용하고, 선 두께와 시각적 크기를 통일한다. 기존 툴팁·단축키 안내를 유지한다.
- 왼쪽 패널은 220px 전후를 기준으로 문서 면적과 균형을 잡는다. 썸네일 크기, 페이지 번호 위치, 선택 표시를 일관되게 한다. Ctrl·Shift 다중 선택과 페이지 드래그 이동을 유지한다.
- 오른쪽 주석 패널은 280–320px를 기준으로 한다. 열리면 문서 영역의 폭을 함께 조정해서 페이지를 덮지 않게 한다. 두 페이지 보기에서도 주석 패널과 문서가 겹치지 않아야 한다.
- PDF가 화면의 주인공이 되도록 문서 주변 여백을 일정하게 둔다. UI 테마가 PDF의 실제 배경색·색상·좌표·배율을 바꾸면 안 된다.
- 본문 편집 도구는 선택한 문단 가까이에 간결하게 배치하되 커서, 입력 중인 글, 편집 손잡이를 가리지 않는다. 편집 위치와 저장 후 결과의 대응을 유지한다.

간격은 4·8·12·16·24px 체계를 사용한다. 버튼 모서리는 6–8px, 패널·팝업은 10–12px 정도로 절제한다. 일반 버튼의 클릭 영역은 최소 32×32px을 확보한다. 반복되는 카드를 쌓거나 불필요한 구분선으로 화면을 잘게 나누지 않는다. 로고는 앱 아이콘·정보 화면 등 필요한 위치에서 사용하고, 문서 작업 공간에 크게 넣지 않는다.

## 4. 기존 기능과 성능 보존

탭 전환, 저장·다른 이름으로 저장, 실행 취소·다시 실행, 검색, 한 페이지·두 페이지 보기, 페이지 편집, 본문 직접 수정, 글꼴 검색, 한글 입력, 형광펜·메모, 메모 이동, 이미지 삽입·이동·크기 조절, OCR, 인쇄, 슬라이드 쇼, 외부 파일 열기 등 현재 제공되는 기능을 유지한다.

창 X의 현재 탭 닫기, 마지막 탭 종료, 전체 종료 단축키, 미저장 내용 확인 등 기존 종료 정책을 바꾸지 않는다. 오류 시 원문과 입력 초안을 유지하는 처리도 보존한다. 기능을 보존한다는 이유로 기존 결함이 해결됐다고 주장하지 않는다.

큰 블러, 모든 버튼에 붙는 그림자, 페이지마다 생성되는 무거운 효과는 피한다. 시각적 상태 갱신 때문에 탭 목록·문서 객체·PDF 렌더링·글꼴 처리를 재생성하지 않는다. 테마 변경과 패널 개폐가 진행 중인 편집 초안, 커서, 선택 상태를 초기화해서는 안 된다.

## 5. 애플처럼 절제된 인터랙션 애니메이션

움직임은 사용자의 조작과 결과의 관계를 명확히 보여줘야 한다. 아래 수치는 윤DF에 적용할 설계 기준이며 애플의 공식 규격을 인용한 것이 아니다. 빠르게 반응하고 부드럽게 멈추는 감속 곡선을 기본으로 하며, 문서 작업 중 과한 탄성과 반복 움직임을 사용하지 않는다.

| 대상 | 동작과 시간 | 적용 조건 |
| --- | --- | --- |
| 도구 버튼 | 호버 배경·아이콘 색 100–120ms, 클릭 시 내부 아이콘만 1→0.97로 70ms 축소 후 140ms 복귀 | 클릭 영역과 주변 배치는 고정한다. 명령은 누르는 즉시 실행한다. |
| 읽기·편집 전환 및 탭 선택 | 선택 배경·표시색을 140ms 동안 전환 | 실제 활성 도구·문서 상태는 즉시 바꾼다. PDF 페이지를 페이드하거나 탭 모델을 재생성하지 않는다. |
| 메뉴·팝업 | 열기 140–160ms: 불투명도 0→1, 내부 내용 y 4→0px. 닫기 100ms | 메뉴의 논리적 위치와 초점·키보드 탐색을 보존한다. 종료 후 숨겨진 메뉴가 입력을 받지 않게 한다. |
| 왼쪽 탐색·오른쪽 주석 패널 | 열기 180ms: 내부 내용 불투명도 0→1, 가장자리 쪽 8px 오프셋→0. 닫기 120ms | 문서 영역 폭은 최종값으로 한 번만 조정한다. 패널 폭을 매 프레임 변경해 PDF를 다시 렌더링하지 않는다. 패널이 문서를 덮지 않게 한다. |
| 썸네일·선택 항목 | 선택 배경과 테두리 120ms | 페이지와 썸네일은 제자리를 유지한다. 다중 선택, 드래그 손잡이와 놓을 위치가 정확해야 한다. |
| 기존 저장 완료·오류 알림 | 등장 160ms, 사라짐 120ms의 불투명도 전환 | 실제 작업 결과를 받은 후에 표시한다. 모션으로 완료 시점을 꾸미거나 가짜 진행률을 만들지 않는다. 기존 알림이 없으면 장식용 알림을 새로 추가하지 않는다. |
| 시작 시 빈 화면 로고 | 한 번만 360ms: 불투명도 0→1, 크기 0.98→1 | 열린 문서가 없는 시작 화면에서만 적용한다. 파일 열기 요청이 있으면 생략하고 즉시 문서를 연다. 스플래시 화면이나 대기 시간을 추가하지 않는다. |

본문 글자, 편집 커서, 선택 영역, 이미지·메모 드래그, 페이지 넘김·스크롤·확대에는 장식용 움직임을 추가하지 않는다. 기존 무한 휠과 페이지 탐색 감각을 유지한다. 작업 중 로고를 반복 재생하지 않는다. 함께 제공되는 반복 GIF는 로고 모션 참고용이며, 프로그램에서는 위의 일회성 시작 동작으로 구현한다.

QML의 `ColorAnimation`, `NumberAnimation`, 상태 전환 등 현재 Qt 버전에서 지원하는 가벼운 기능으로 구현한다. 감속은 `Easing.OutCubic`을 기본으로 사용한다. 시각적 색상·불투명도·내부 콘텐츠 위치에만 필요한 애니메이션을 연결한다. PDF 좌표·페이지 크기·문서 모델 속성에 전역 `Behavior`를 붙이지 않는다. 초점과 클릭 판정은 실제로 보이는 UI와 일치해야 한다.

연속 조작 시 애니메이션을 대기열에 쌓지 말고 현재 시각 상태에서 새 목표 상태로 이어간다. 실행 중 다시 닫거나 탭을 바꿔도 이전 애니메이션 완료 콜백이 새 상태를 덮어쓰면 안 된다. 애니메이션 종료를 기다려 저장·탭 전환·닫기를 실행하지 않는다. 숨겨지거나 파괴된 화면의 효과는 중단하고 입력을 막는 오버레이가 남지 않도록 한다.

설정에 ‘동작 줄이기’를 제공한다. 켜면 확대·축소·이동 효과를 끄고 즉시 전환하거나 80ms 이하의 짧은 페이드만 사용한다. 작업 중인 상태를 유지하면서 설정을 적용한다. 애니메이션을 사용하지 않는 경우에도 모든 동작과 정보가 동일하게 전달되어야 한다.

## 6. 구현 순서와 완료 기준

먼저 실제 소스 구조와 현재 화면을 확인하고 변경 대상·유지할 동작을 짧게 정리한다. 제공된 0.9.8 소스는 PySide6와 Qt Quick/QML 기반이며, `ui/Theme.qml`, `ui/Main.qml`, `ui/ActionButton.qml`, `ui/Icon.qml`, `ui/CommentsPanel.qml`, `ui/InlineTextEditor.qml`, `ui/FontPicker.qml` 등이 관련 파일이다. 다른 버전이 제공되면 해당 버전의 실제 구조를 먼저 확인한다.

색·서체·간격 토큰을 정리한 뒤 탭·도구줄·사이드바·주석 패널·편집 도구·대화상자 순서로 작은 범위씩 적용한다. 정적인 화면과 기능이 정상인 것을 확인한 뒤 모션을 적용한다. 작업 전후 화면을 같은 문서·페이지·배율로 비교한다. 기존 테스트를 활용하고, 디자인 변경이 실제로 영향을 줄 수 있는 동작만 추가 검증한다.

1320×900 기본 창과 1000×640 최소 창에서 긴 파일명, 여러 탭, 양쪽 패널, 두 페이지 보기, 본문 편집 상태를 확인한다. 가능한 환경에서 Windows 100%·125%·150% 배율의 글자 잘림·버튼 겹침·클릭 위치를 확인한다. 탭 전환, 편집 중 Ctrl+S, 입력 적용·취소, 주석 패널 개폐, 이미지·메모 드래그, 종료 확인이 유지되는지 점검한다.

추가로 패널을 빠르게 반복 개폐하고, 전환 도중 다른 탭을 누르거나 Ctrl+S·닫기를 실행하며, 동작 줄이기를 전환해도 최종 상태와 입력이 정확한지 확인한다. 편집 중인 문단과 커서가 움직이거나 사라지지 않아야 한다. 모션을 켰을 때 PDF 렌더링 요청이나 글꼴 작업이 불필요하게 늘지 않는지 확인하고, 관련 성능 측정은 동일한 시험 문서와 조건에서 수행한다.

최종 결과로 수정된 소스, 실제 앱 화면의 전후 비교, 버튼·메뉴·패널 모션을 보여주는 짧은 실행 영상, 변경 요약, 수행한 검증과 남은 미검증 항목을 제출한다. 실행하지 않은 화면이나 Windows 실기기 검증을 완료했다고 쓰지 않는다. 시안 설명만으로 끝내지 말고 실제 앱의 UI 변경까지 완료하라.
